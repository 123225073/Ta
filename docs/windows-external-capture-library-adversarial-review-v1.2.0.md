# Ta Windows v1.2.0 外部截图与素材库对抗审查

## 审查范围

- 外部剪贴板来源归因、读取竞态和签名可信度。
- 素材库无限历史、日期归档、迁移、缩略图、删除与批量导出。
- 设置开关、明确粘贴、搜索/日期筛选和跨分页选择。

## 对抗发现与修复

| 风险 | 原问题 | v1.2.0 修复 |
|---|---|---|
| P1 错收或串读 | 元数据事件与 Electron 读取图片可能不是同一 sequence | 监听器生成稳定快照；读取前后各执行一次 `inspect`，同时比较 sequence、PID、路径、证书指纹 |
| P1 迁移丢图 | 异步迁移游标可能漏掉迁移期间新增素材 | 主进程写操作等待存储迁移，底层迁移锁拒绝绕过队列的直接写入 |
| P1 大图 OOM | 卡片可能直接解码 120MP 原图 | 限制 32MP/80MB；Sharp 直接从文件生成 480×320 受限缩略图，渲染层不接触原图 |
| P2 来源冒充 | 签名结果曾按路径、长度和时间戳缓存 | 移除弱缓存；保持所有者进程句柄直到验签和路径复核完成；TS 同时校验证书主题与指纹格式 |
| P2 主线程卡顿 | 大批量导出使用同步 `copyFileSync` | 产品路径改为逐张异步 `copyFile`，同名使用排他创建并自动编号 |
| P2 删除不一致 | 回收站后缺文件分支的 tombstone/索引删除不在同一事务 | 缺文件与有文件路径均使用数据库事务，旧迁移项删除后不再复活 |
| P2 静默失败 | 旧历史迁移错误只留在进程内 | 素材库显示失败数量、首条原因和“重新迁移”入口 |
| P2 监听失控 | 总开关关闭仍可能运行，异常退出固定重启 | 仅在总开关和应用开关有效时运行；输出设上限，重启指数退避 |
| P2 快捷键意图冒充 | 通用应用意图或注入按键可能把普通复制误认成截图 | 仅飞书可消费意图；拒绝注入按键，并绑定新出现的置顶飞书浮层 PID、完整路径、触发前 sequence；浮层关闭后 1 秒失效 |
| P2 选择不完整 | “选择当天/全选”可能只覆盖已加载页 | 改用筛选选择协议，由主进程按 SQLite 游标遍历全部匹配项 |
| P2 跨时区错组 | UI 曾按当前时区从 UTC 时间重算日期 | 数据库持久化 `dateKey` 贯穿契约、分组与筛选，归档日不随系统时区变化 |
| P2 迁移期内存增长 | 截图图片曾在迁移屏障前以 Buffer 无界等待 | 最多 2 个采集任务；图片原子暂存到 100 文件/512 MB 有界目录，重启恢复并单线程排空；异常项隔离且继续后项 |

## 验证证据

- `npm test`：15 个测试文件、80 项测试通过；包含 1,025 条真实临时文件分页、筛选、去重、迁移回滚、迁移写锁、旧历史 tombstone、跨时区日期、暂存容量/恢复/隔离、QQ 意图旁路拒绝和异步导出。
- `npm run typecheck`、`npm run build` 通过。
- `npm run smoke:clipboard`：本机真实微信剪贴板快照通过，owner 为 `Weixin.exe`，`stable=true`，包含 `WeChatScreenshotFormat` 专属标记、图片格式与有效腾讯签名元数据。
- `npm run smoke:e2e`：真实双屏 GDI 截图、结果持久化、素材库路由/日期/搜索/聚焦粘贴、EXIF 旋转归一化及既有截图功能全部通过。
- 负向现场证据：监听器捕获到已签名的 Coodesker 非图片剪贴板事件，因不在应用白名单且 `imagePresent=false` 被失败关闭，未读取或入库。

## 尚未伪造的边界

飞书当前运行实例拒绝合成 `Ctrl+Shift+A`，Windows GUI 捕获接口同时返回 `0x80004002`，因此未把“自动脚本代替用户完成飞书框选并点击保存”写成通过项。严格规则已移除猜测性的飞书/QQ 格式名以及跨应用通用的 `application/x-capturer-status`：微信使用真实 `WeChatScreenshotFormat`；本机 QQ 9.9.31 已确认调用腾讯有效签名的独立 `QQScreenshot.exe`；飞书依据官方默认 `Ctrl+Shift+A`，由原生监听器绑定“物理快捷键 → 新出现的可见置顶 Feishu.exe 浮层 → 同一 PID/路径的新剪贴板 sequence”。浮层关闭超过 1 秒、自定义飞书快捷键或界面按钮无法确认时仍会拒绝，不会拿普通复制冒充截图。
