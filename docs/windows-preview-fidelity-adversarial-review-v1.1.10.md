# Ta Windows v1.1.10 清晰度与快速截图对抗审查

审查日期：2026-08-28

## 用户可见故障

1. 进入截图框选后，默认选中窗口中的文字和细线明显发糊。
2. 所有截图已经默认复制，“复制图片”作为独立功能名称重复；用户需要一个保存并退出、不会弹出编辑页的快速路径。

## 可复现反馈环

命令：`npm run test:preview-fidelity`

修复前稳定失败：

```text
预览必须无损，当前格式为 jpeg：\\.\DISPLAY1
```

代码证据：旧辅助进程将每块屏幕限制为最大 896px 宽，使用双线性插值缩小，再以 JPEG 76 保存；3072px 主屏在覆盖层中被放大约 3.43 倍。最终裁图虽然来自全分辨率 BGRA，但用户框选时看到的是低分辨率 JPEG，因此“结果清楚、框选画面模糊”会同时发生。

## 假设与反证

| 排名 | 假设 | 预测 | 结果 |
|---|---|---|---|
| 1 | 896px JPEG 被重新放大 | 全分辨率无损预览会消除降采样链路 | 命中；代码和回归测试均确认 |
| 2 | Chromium 或 DPI 二次缩放 | 即使输入图与屏幕同尺寸，像素仍会发生不可解释的重采样 | 未命中；PNG 尺寸、物理像素映射和最终源一致 |
| 3 | 蒙版/透明窗口滤镜造成模糊 | 选区计算样式中应存在 `filter`/`backdrop-filter` 或非透明填充 | 未命中；四片外部蒙版无滤镜，选区内部透明 |

## 修复后的对抗断言

- 每块预览必须是 PNG，宽高必须等于该显示器物理像素宽高。
- 从预览解码的 RGBA 与最终 BGRA 原图抽样通道转换后平均差异不得超过 0.1。
- 不能为了清晰度退回同步创建覆盖层或鼠标移动时重新截图。
- 快速截图必须同时满足：复制哈希等于落盘 PNG、历史增加一项、动作仍兼容旧 `copy` 标识、主界面保持工作台且编辑页不显示。
- 通用截图仍打开结果页；取字、翻译、钉图、长截图的既有分支不得被快速截图改变。

## 性能结果

本机双显示器 3072×1920 + 2560×1440：原生辅助进程在全分辨率无损 PNG 下，连续三次冻结阶段约 165–238ms，完整 BGRA 写入约 199–273ms。最终安装版端到端运行的输入接管/冻结/完整预览首次为 71/333/526ms，连续为 43/292/393ms；裁剪鼠标最大/平均帧间隔 9/8ms。

因此本次没有用重新引入低清缩略图的方式追求数字延迟，也没有在鼠标移动链路中增加原生调用。
