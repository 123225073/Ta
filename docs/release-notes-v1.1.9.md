# Ta Windows v1.1.9

发布日期：2026-08-28

## 微信式智能框选

- 截图冻结画面后，自动高亮鼠标下最上层的 Windows 窗口；单击锁定窗口，拖动超过 4 DIP 时自动切换为自由框选。
- 自动选中后仍可移动、八方向缩放，并保留双击、`Enter` 和“完成”按钮确认。
- 设置页新增“自动识别鼠标下的窗口边框”，默认开启；关闭后保留原来的自由框选。
- 自动识别不调用 AI，也不在鼠标移动时查询系统：窗口候选与屏幕像素在同一次截图开始时冻结，移动只做本地命中测试。

## 选区颜色修复

- 删除覆盖整个冻结画面的暗层和超大外阴影组合，改为上、右、下、左四片外部蒙版。
- 候选或已锁定选区内部不再叠加透明度、灰度或亮度滤镜，保持冻结画面本身的颜色；四周统一灰暗一次，不再双重变暗。
- 最终复制、保存和历史记录继续从原始全分辨率 BGRA 截图源裁剪，不从带蒙版的界面截取。

## Windows 原生实现

- 原生截图辅助进程同次调用 `EnumWindows`、`DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`，失败时回退 `GetWindowRect`。
- 排除截图覆盖层本身、不可见、最小化、DWM cloaked、系统桌面和极小窗口；保留窗口 Z 序。
- 窗口跨屏时按每块显示器物理边界裁剪，再转换为对应 Electron 覆盖层的本地 DIP；支持不同缩放率和负坐标显示器。

## 验证

- 10 个测试文件、37 个测试通过；TypeScript、生产构建和源码真实桌面 E2E 通过。
- 双屏 E2E 覆盖 175%/125% 缩放、窗口悬停预选、单击锁定、四片蒙版、选区透明、无全屏暗层、设置保存、自由框选、移动、缩放、双击和默认复制。
- 本轮安装版实测截图输入接管 67 ms、冻结预览 225 ms；自动窗口识别没有增加鼠标移动阶段的 IPC 或原生查询。

## 能力边界

- v1.1.9 是顶层窗口级识别，不宣称能够识别窗口内部每一个按钮、表格或 SAP 控件。
- UI Automation 控件级吸附和冻结画面像素边缘兜底保留为后续能力，避免把慢查询重新带回当前低延迟路径。
- 微信 Windows 截图的内部技术实现没有公开；本版本参考其可观察交互，工程路线基于 Microsoft 与 Electron 的公开接口。
