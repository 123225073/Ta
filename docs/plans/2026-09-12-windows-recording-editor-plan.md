# 拓 Ta Windows：录屏与录后编辑开发计划

日期：2026-09-12。

状态：需求分析和开发规划完成；功能代码、上游构建、录制与导出实测尚未执行。本文中的目标、拟新增文件和验收指标均不是已完成能力。

## 1. 产品判断与已确认边界

目标是让日常操作从“随手录下来”直接走到“整理成可以交付的视频”，降低启动、解释和返工成本。首版要覆盖录制、录中标记、录后编辑、选择性导出、再次打开项目五个环节。

用户已明确：

- 可以全屏录制，也可以自由框选区域。
- 录制中能标记；录完以后还能重新添加、修改和删除标记。
- 导出时可以选择哪些标记融合进成片。
- 标记绑定原始视频画面位置，随剪辑中的缩放、平移、裁剪保持对齐。
- 不要求识别物体，不要求跟随页面滚动、目标运动、遮挡或重新出现。动态目标跟踪不进入本次开发计划，也不引入相关模型、依赖和界面。
- 尽量使用已有开源录制与编辑基础。

首要验收场景：录两分钟操作，在录制中画两处标记；结束后删除其中一处，补一个文字说明，剪掉等待片段，并放大重点区域。分别导出带选定标记和不带讲解标记的两份 MP4；重新打开项目仍可继续修改。

## 2. 应该具备的功能与理由

### 2.1 首个可用版本必须完成

| 编号 | 功能 | 为什么需要 | 首版范围 |
|---|---|---|---|
| R01 | 快捷开始 | 问题出现时不必先打开复杂工作台 | 工作台、托盘、可自定义全局快捷键；记住上次设置 |
| R02 | 范围选择 | 避免录进无关桌面，也支持跨应用说明 | 单块显示器全屏、该屏内自由框选、单窗口；开录前可移动和缩放选区 |
| R03 | 暂停、继续、停止 | 等待、临时中断时不需要重录 | 暂停同时停止有效音视频时间推进；快捷键可用；暂停期间不占成片时长 |
| R04 | 声音选择 | 既能无声展示，也能边操作边说明 | 麦克风和系统声音独立开关；麦克风设备选择、音量指示；两类声音独立保留 |
| R05 | 录制中标记 | 当场讲清楚重点 | 矩形、箭头、画笔、高亮、文字、编号；颜色、粗细；撤销、清除当前显示标记 |
| R06 | 录后标记 | 录制时没有想清楚也可事后补充 | 新增、选择、移动、缩放、改字、删除；标记列表；开始和结束时间 |
| R07 | 基础剪辑 | 去掉开头准备、等待、错误尝试 | 裁头裁尾、分割、删除选中片段并自动闭合空隙；撤销和重做 |
| R08 | 裁剪及局部放大 | 让文字清楚，让接收者知道看哪里 | 全片统一裁剪范围；选定时段放大某区域、调整中心和倍率、恢复全景；固定成片画布 |
| R09 | 标记随画面变换 | 满足已明确的核心需求 | 与原始画面共用变换规则；编辑器窗口缩放、视频放大、平移、裁剪、导出分辨率变化均不漂移 |
| R10 | 选择性导出 | 一次录制可给不同对象使用 | 按单个标记或类别选择；选定讲解标记/全部讲解标记/不带讲解标记；预览反映当前导出选择 |
| R11 | 声音整理 | 不必因为音量或某段失言重新录制 | 两轨分别调音量或静音；可静音选定片段；剪辑后与画面同步 |
| R12 | 保存和恢复 | 录制成果不能依赖编辑器一直开着 | 自动保存可编辑项目、录制分段落盘、异常片段恢复、重新打开编辑；原素材与成片分开 |
| R13 | 本地录屏列表 | 录完能找到，日后能接着改 | 在现有素材库中增加“录屏”子视图；缩略图、名称、时长、日期、打开项目、导出记录 |
| R14 | 可靠交付 | 收到文件就能播放 | MP4（H.264 视频/AAC 音频，实际编码器先验证）；原尺寸及按比例的 1080p/720p 档；导出进度、取消、完成后打开所在文件夹 |
| R15 | 固定区域遮挡 | 日常软件演示可能含不应交付的字段 | 录后添加不透明遮挡；随画面变换，独立于讲解标记选择；不是动态跟踪，也不宣称清除了原素材中的内容 |

R15 是推荐纳入的实用功能，交互保持简单。默认优先不透明遮挡；模糊和马赛克样式可后置。导出“不带讲解标记”不自动关闭遮挡；关闭某处遮挡要直接操作该对象，预览随之更新。

### 2.2 默认行为，减少每次开录的选择

- 首次提供区域录制，之后记住录制方式；保存的区域须在显示器布局变化后重新核验。
- 默认 30 fps、保留选区原始像素；小画面不强行放大到 1080p。高分辨率不能靠“保留像素”保证编码质量，仍须验证文字可读性。
- 麦克风、系统声音首次均关闭；开录页显式显示状态，之后记住用户选择。设备失效时明确提示，不能把“有音轨”当成“有声音”。
- 默认 3 秒倒计时，可取消；计时器从第一份有效录制数据开始，而不是从点击按钮开始。
- 一个录制会话固定输出尺寸。区域录制期间不移动录制框；单窗口模式由原生窗口标识选定，不仅按标题字符串匹配。
- 关闭主窗口可继续托盘录制，浮条和停止快捷键仍有效；真正退出程序时明确提供停止并保存的操作，不能直接结束录制进程而丢掉素材。
- 窗口尺寸变化时先等比适配固定录制画布；窗口最小化、关闭、显示器拔出或锁屏导致源不可用时自动暂停并提示，不静默录长段黑屏。恢复后由用户继续。
- 默认鼠标直接操作原软件；显式切入标注模式，Esc 返回操作模式。全局停止键与 Esc 的编辑语义分开。
- 箭头、矩形、文字和编号默认从创建时显示到主动清除或停止；高亮和画笔默认同样持续，避免额外的自动消失规则。录后可改时长。
- “清除当前标记”结束这些对象的显示时间，保留此前的显示历史；“撤销上一笔”撤回对象。停止录制后录中标记和录后标记均可编辑。
- 编辑中删除片段不删除源文件；导出不覆盖源文件。已有同名成片采用新名称，覆盖必须由用户明确选择。
- 普通 MP4 是最终合成文件；可再次取消标记的是本地项目，不是已经发送出去的 MP4。

## 3. 界面与工作流

全部界面遵守根目录 DESIGN.md，沿用夜幕/瓷白主题、既有字体、颜色、间距、导航和快捷键设置习惯。

1. 工作台增加“录制视频”入口，托盘和快捷键进入同一个选择流程。
2. 开录面板只放范围、声音、倒计时和开始；选区框支持拖动、边角缩放以及尺寸显示。
3. 录制浮条显示计时、暂停/继续、标注、声音状态和停止；可以移开，不能出现在原始视频中。
4. 停止后先确认素材已落盘，再打开编辑器。停止完成不以“成片已经导出”表示。
5. 编辑器以视频为中心，下方一条主时间轴；右侧按当前任务显示标记属性或导出选项。不要要求普通用户管理专业剪辑轨道。
6. 用户选择片段后可以删除、静音或放大重点；选择标记后调整内容和显示时长。
7. 导出前直接看按当前选择合成的预览。遮挡单独列出；成片和可编辑项目在录屏详情中分别打开。

缩放要分清两个入口：“预览大小”仅影响编辑工作区，“放大重点”写入成片。标记在两种情况下都保持对齐，前者不改变成片内容。

## 4. 技术规则：从源头保证可编辑

### 4.1 录制内容分离

- 干净屏幕视频、系统声音、麦克风声音、标记事件和编辑项目分别存储；音轨可以放在同一容器的独立轨道，也可分文件，但不能先混成一条后宣称可分开编辑。
- 应用浮条、录制边框、标注层必须从采集源排除。只隐藏工具栏、却把笔迹烘进原画面，不满足需求。
- 不沿用长截图的“每次采集前隐藏、采集后恢复”作为视频方案，避免连续录制中的闪烁和时序问题。
- 原生采集与音频编码优先使用已有实现；不循环调用现有 PNG 截图再拼视频，不用大段 data URL 搬运视频。
- 区域录制须在写入源媒体前裁掉选区外像素；不能在后台保留整个桌面，只在导出时裁剪却把它称为区域录制。
- 编辑器和编码工作不能阻塞 Electron 主进程；捕获/编码辅助进程仅处理本会话，退出时清理自身资源，不影响其他应用。

### 4.2 坐标和时间只有一套含义

- 标记的位置、尺寸、箭头端点和画笔路径保存在源视频坐标系；保存时记录源宽高，时间使用源媒体时间，不使用当前编辑窗口坐标。
- 录制框从 Windows 桌面坐标映射到选区局部物理像素；处理多显示器负坐标和 125%/150% 等缩放比例。
- 显示变换由源裁剪、局部放大/平移和输出适配共同组成。标记的几何与笔画、字号随同一内容变换缩放；选中对象时的控制点属于编辑 UI，不进入成片。
- 鼠标在已放大的预览上新增标记时，必须逆向映射回源坐标。不能只有“旧标记缩放正常”，而新画的框位置不对。
- 超出裁剪范围的标记按视频内容边界裁掉；不能浮到留白或其他内容上。
- 编辑片段保存源起止时间，成片时间由保留片段依次拼接计算。删除一段后，声音、标记、缩放效果使用同一映射，避免错位。
- 标记跨越被删片段时，只渲染其与保留片段重叠的部分；完全落在删除区间的标记不进入成片，但可通过撤销恢复。
- 录制中绘制的笔迹保存绘制时间；清除结束显示区间。暂停期间不新增带有歧义的录制标记；UI 清楚显示暂停状态，继续后再标注。
- 预览和导出使用同一场景数据、时间采样规则及坐标计算；若使用不同渲染后端，以固定样片进行像素位置对照验证。

### 4.3 文件与恢复

- 独立项目目录建议为 `录屏/年/月/日/项目ID/`，包含版本化项目文件、媒体、缩略图、录制清单和导出记录。
- 视频保存位置使用独立的持久化设置，初始建议为用户“视频”目录下的“拓 Ta”，设置中可修改。旧项目保留各自受控根目录引用；修改位置只影响新项目，首版不擅自迁移视频。现有图片库迁移和缩略图清理不能遍历或删除视频项目。
- 项目内容至少有：schemaVersion、源文件 ID、宽高/时基/时长、保留片段、标记对象、缩放区间、全片裁剪、两轨声音设置、导出选择和修订号。
- 项目采用临时文件写入后原子替换并保留最近有效版本；媒体以可恢复的分段/分片持续落盘，不把整段视频留到停止时才写入。
- 突然退出后恢复已完成分段，未完整写入的末尾段标记为损坏；恢复范围必须根据实测说明，不能承诺绝不丢帧。
- 导出基于固定项目修订快照。导出期间继续编辑不会改变本次输出；进度和文件完成状态一致。
- 导出取消、编码失败、磁盘不足不删除原素材和项目；先写临时输出，成功后才成为正式成片。
- 录制期间持续监测可用空间，预留封装和项目保存空间；空间不足时停止采集并尽量完成已有内容保存，不自动删除历史视频。
- 视频素材支持索引和按需读取，不能整段读进内存。退出编辑器不丢项目，删除项目需要明确列出原素材与成片的影响。
- 首版遮挡是输出效果，原素材仍保留原画面。界面在使用遮挡时说明这一点；不自动打包或分享原素材。

## 5. 开源复用决策

### 5.1 首选候选：OpenScreen v1.11.0

2026-09-12 检索到的正式发布为 v1.11.0，发布页显示 2026-09-09，短提交号 `47ab52f`。开发先锁定此候选标签并解析完整提交 ID，不能跟着 main 自动漂移。它是社区续作，原作者仓库已归档。

已核对：

- 有 Electron/React/TypeScript 编辑基础、Windows 原生采集、录后剪辑、缩放、独立标注对象、项目及导出流程。
- Windows 采集 helper 位于 `electron/native/wgc-capture`，构建依赖 MSVC、CMake/Ninja；D3D11 合成插件涉及 Rust 和固定版本的 FFmpeg 动态库。
- 主项目 MIT；其第三方说明明确列出 FFmpeg、运行库等额外许可和打包要求。不能只保留一个 MIT 文件就视为依赖处理完成。
- 文档存在不同年代导出链路的描述，具体调用路径以锁定版本源码和实际构建为准，不根据 README 推断当前运行后端。

优先复用范围：采集 helper、媒体探测/编码/封装和导出实现、项目及时间轴处理、已有缩放数学和相关测试。按实际依赖闭包评估，保留上游来源、许可、文件清单和修改记录。

不能直接认定现成满足：独立录中标记、两种声音独立可编辑、标记与视频共用变换、当前机器的遮罩排除兼容性、区域模式及异常恢复。

集成策略：在 Ta 中新增独立录屏模块，通过窄接口连接现有程序；优先复用实现而非整套替换现有客户端。暂不引入上游 AI、摄像头、自动更新、遥测和云服务。上游 Electron/React 版本不同，需要重新构建和适配，不能直接复制原生二进制或升级整个 Ta 作为捷径。

其他项目的用途保持限定：Screenity 参考录中标注操作；Cap 参考本地录制和音频处理；OBS 参考捕获/编码边界。本次不引入目标跟踪，也不需要 Kdenlive/OpenCV 运行时。

| `windows/electron/main.ts` | 负责窗口、托盘、快捷键和 IPC，已经较大 | 仅注册录屏模块/窗口路由，具体状态机和编码放入新模块 |
| `windows/electron/contracts.ts`、`renderer/src/types.ts` | 双侧类型，CaptureAction 仅含截图动作 | 独立录屏动作和契约，不把视频路径伪装成 CaptureResult.imageDataUrl |
| `windows/electron/library.ts`、`store.ts` | 素材存储及缩略图处理针对 PNG | 新增视频项目存储与单独索引，素材库增加录屏子视图；不把视频送进现有 PNG 校验/Sharp 流程 |
| `windows/electron/preload.ts`、`validation.ts` | 白名单接口与输入校验 | 增加录制开始/暂停/停止、项目保存/读取、导出/取消及事件订阅；限制来源窗口和项目 ID |
| `windows/renderer/src/App.tsx`、`main.tsx` | 现有首页/素材库/设置/结果及子窗口入口 | 增加录屏入口、选择器、浮条、独立视频编辑页面；保留截图编辑流程 |
| `windows/renderer/src/Editor.tsx` | 图片标注，导出为单张 data URL | 可参考工具语义和绘制逻辑；不能直接把原图片编辑器变成视频编辑器 |
| 全局快捷键注册 | 当前回调统一调用 startCapture，录制快捷键设置会 unregisterAll | 增加动作分发及会话快捷键管理；防止设置保存/快捷键编辑导致录制停止键失效 |
| 权限处理 | 默认拒绝 Electron 权限请求 | 优先原生采集；若需媒体权限，仅按已选源与录制窗口授权，不能全局改成允许 |
| `ta-media` 协议 | 按图片 ID 读取文件 | 为视频增加受控媒体流，验证随机拖动进度、Range/大文件读取和项目路径边界 |
| TypeScript 构建 | 主进程 rootDir 为 electron，渲染侧独立配置 | 共用数学/项目代码先放在 electron/video 内不依赖 Node 的模块，渲染侧按需导入；验证 Vite 与类型检查，避免移动整个构建根目录 |
| NSIS / resources | 已有 OCR、截图 helper 随包资源 | 只加入实际需要的录制/编码依赖和许可；保持设置、截图历史和原文件 |

新增模块建议：`electron/video/{contracts,project-store,recorder,ipc,media,export,geometry,timeline}.ts` 与 `renderer/src/video/` 下的选择器、浮条、编辑器、录屏列表。名称为规划，实际按锁定上游的依赖结构细化。

录制会话状态建议：空闲→选择→准备→录制↔暂停→保存收尾→可编辑；异常进入可恢复状态。停止动作幂等，不允许两次快速点击创建两份收尾任务。导出是独立任务，不与录制状态混用。

录制时普通截图能力应继续可用，截图覆盖层也须验证不会进入视频；全局快捷键不被静默替换。长截图会主动滚动屏幕，若与录制共用资源或干扰操作，在调用时清楚提示并提供先暂停，不自动中止或废弃录制。

## 8. 必要验证

以下为拟定验收目标，不是本轮测量结果：

1. 三种范围各录制一次，覆盖主副屏、负坐标和常用 DPI；区域外内容不进入输出，视频文字清楚。
2. 在有动态背景的测试区域绘制标记，再导出不带标记版本，确认被覆盖内容完整；验证工具栏与录制边框排除。
3. 对源画面已知网格坐标画框，执行非中心裁剪、缩放、平移和不同输出尺寸；角点投影偏差目标不超过 1 个输出像素，抗锯齿颜色差异不作为漂移。
4. 在已放大的预览中新增标记，再恢复全景、关闭重开、导出；定位一致。
5. 删除中间片段，包括与标记/放大区间部分重叠或完全覆盖；声音、标记和缩放均按保留片段正确映射。
6. 录中清除、撤销、停止；录后按单个对象和类别取消；遮挡不被“不带讲解标记”顺带关闭。
7. 麦克风/系统声音分别和同时录制，分别静音；至少覆盖 30 分钟含暂停/继续的同步样片，用闪光与提示音测量开头、中间和结尾，偏差目标不超过 100 ms。
8. 60 分钟持续录制记录 CPU/GPU/内存/文件大小，检查内存不随视频长度持续无界增长；不据短样片宣称支持长录制。
9. 在隔离测试目录模拟异常退出、磁盘不足和设备失效；恢复完成分段，不把损坏尾段或半成品标为成功；不操作真实历史文件。
10. 导出取消和重试、同名输出、项目修改期间导出、重新打开项目；源素材哈希不变，成片可用系统播放器播放。
11. 双主题、缩放显示、键盘操作、浮条鼠标穿透/标注切换、停止键有效性符合 DESIGN.md 和既有习惯。
12. 按影响范围运行现有 `typecheck`、`test`、`test:preview-fidelity`、`build`、`smoke`、`smoke:e2e`，涉及剪贴板时运行 `smoke:clipboard`。打包使用既有 `dist`，安装后复核截图、长截图、钉图、图片右键、设置及历史保留。模型服务凭据和真实调用不作为录屏验收前置。

纯数学/时间映射及存储恢复用自动测试；采集排除、设备声音、原生编码和安装用实际样片验证。不能以按钮存在、编译成功或上游 README 功能表代替端到端验收。
