# Ta Windows v1.1.9 智能框选对抗审查

审查日期：2026-08-28

## 第一性原理

截图交互必须同时满足三个互不替代的条件：冻结画面不能被底层应用继续改变；选区内部不能被截图层改色；自动框选不能通过高频系统查询重新制造输入卡顿。由此确定“同次冻结像素与候选、渲染层本地命中、四片外部蒙版”的实现。

## 失败模式与防护

| 对抗场景 | 可能后果 | 实现与验证 |
|---|---|---|
| 全屏暗层仍覆盖选区 | 所选内容发灰，透明选区无法恢复颜色 | 删除全屏 `::after`；只渲染四片外部蒙版，E2E 验证选区背景透明且伪元素不存在 |
| 暗层与超大阴影叠加 | 选区外双重变暗、GPU 合成异常 | 选区仅保留边框和普通阴影，变暗职责只有四片蒙版 |
| 四片蒙版使用实时灰度滤镜 | 双高分屏冻结瞬间产生 GPU 合成长帧 | 改用中性灰半透明遮罩，不使用 `backdrop-filter`；选区仍不受遮罩影响 |
| 覆盖窗口原生透明度恰为 0 | Chromium 将窗口判为不可见并暂停动画帧，恢复时表现为鼠标停顿 | 准备阶段保持 1% 原生透明度，页面自身全透明；输入与动画持续，桌面像素不变 |
| 把截图覆盖层识别为目标 | 自动框选永远命中整屏自身 | 主进程读取覆盖层 HWND 并在原生枚举请求中排除 |
| 鼠标移动时查询 Win32/UIA | 鼠标停顿、截图启动后卡顿 | 候选在截图瞬间一次性生成；`pointermove` 只遍历内存数组，无 IPC、PowerShell 或重新抓屏 |
| 重叠窗口选中后层 | 与肉眼所见不一致 | 保留 `EnumWindows` Z 序，命中时选取第一个包含鼠标的候选 |
| 最小化或虚拟桌面窗口混入 | 高亮不存在的内容 | 排除 `IsIconic`、`DWMWA_CLOAKED` 和不可见窗口 |
| 无标题窗口被丢弃 | 自绘/工具窗口无法自动框选 | 标题只用于显示，不作为候选有效性的必要条件 |
| 125%/175% 混合 DPI | 框线相对窗口偏移 | 每块屏幕分别用物理捕获尺寸到本地 DIP 的 X/Y 比率映射；双屏真实 E2E 通过 |
| 跨屏窗口越界 | 候选跑出当前覆盖层 | 先按物理显示器边界求交集，再映射和二次钳制 |
| 自动候选抢走自由框选 | 用户无法选择窗口的一部分 | 按下后移动超过 4 DIP 即清除自动候选并进入手动画框 |
| 单击自动完成 | 无法校正窗口边界 | 单击只锁定；之后仍可移动、缩放，确认动作独立 |
| 设置关闭不生效 | 用户无法退回纯手动方式 | 设置经 IPC 布尔校验并持久化；E2E 完成开启→关闭保存断言 |
| 候选数据伪造或越界 | 截图裁剪异常 | 候选来自受控本地辅助进程；最终用户选区仍在主进程 IPC 边界按显示器尺寸校验 |

## 自动验证证据

- 单元测试：Z 序命中、最小候选拒绝、四片不重叠蒙版、边缘钳制、物理坐标到 DIP、跨屏裁剪。
- 双屏 E2E：175% 主屏和 125% 副屏；绿色顶层见证窗口被识别，边界误差在 4 DIP 内；单击后锁定尺寸一致。
- 交互 E2E：自由创建、松开保留、移动、八向缩放、双击确认和默认复制继续通过。
- 性能 E2E：安装版启动阶段 30 帧最大/平均间隔 75/11 ms，裁剪阶段 9/8 ms；覆盖窗口连续复用增长为 0。
- 捕获完整性：原始源、裁剪源、落盘 PNG 和连续多轮捕获均通过非黑、非透明及绿色见证像素断言。

## 保留边界

- 当前识别对象是 Windows 顶层窗口，不是窗口内部控件。UI Automation 可能被自绘应用拒绝或阻塞，所以没有在本版本中冒充稳定能力。
- 快速冻结预览仍是缩放 JPEG；蒙版不会再改变选区颜色，最终图片也来自原始 BGRA，但预览在像素级可能存在轻微 JPEG 色差。若未来要求预览逐通道完全一致，应在不阻塞输入的前提下异步替换为无损全分辨率画面。
- DRM、系统安全桌面与受保护视频可能由 Windows 强制显示为黑色；软件不绕过操作系统保护。
