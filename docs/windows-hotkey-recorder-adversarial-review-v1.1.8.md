# Ta Windows v1.1.8 快捷键与双屏捕获对抗审查

审查日期：2026-08-28

## 第一性原理

快捷键设置的输入对象不是字符串，而是一次可验证的键盘手势。系统必须准确区分修饰键、主键、取消、清空、软件内重复和操作系统占用；录制过程本身不能触发原快捷键。截图后端则必须逐屏保持结果独立，不能因一块显示器的内容特征替换其他显示器已经成功取得的像素。

## 攻击场景与结果

| 攻击场景 | 风险 | 防护与验证 |
|---|---|---|
| 用户只按 Ctrl/Alt/Shift | 过早保存不完整组合 | 保持录制状态并提示继续按主键 |
| 用户按普通单字母或数字 | 全局劫持日常键盘输入 | 拒绝保存，要求至少一个修饰键；F1–F24 允许单独使用 |
| 录制的是当前生效快捷键 | 按键时直接启动截图 | 输入框聚焦即暂停全部全局快捷键，失焦或组件卸载后恢复 |
| 两项功能录入同一组合 | 一个组合触发结果不确定 | 规范化 `Ctrl/Control/CommandOrControl` 等别名并阻止保存 |
| 录入 Alt+F4 等系统保留键 | Electron 注册失败 | 保存后读取真实注册状态，明确提示“被 Windows 或其他软件占用” |
| 用户要取消或禁用 | 被迫覆盖原值或手写空串 | `Esc` 取消；`Backspace/Delete` 清空，空值按禁用处理而非冲突 |
| 升级前保存的是 `CommandOrControl` | Windows 页面仍显示开发者语法 | 兼容旧值并显示为 `Ctrl + …`，升级不改写用户设置文件 |
| 保存自定义值后返回工作台 | 首页继续显示旧默认值 | 工作台从实际设置读取；`Alt + F1` E2E 回显通过 |
| 一块副屏是纯黑内容 | 所有显示器被判失败并整体回退 DXGI | GDI 结果逐屏保留，合法黑屏不触发全局后端切换 |
| DXGI 在当前驱动会话失败 | 截图长时间卡住或得到黑帧 | 正常 Windows 安装路径固定使用预热 GDI；已成功 GDI 不再转入 DXGI |

## 实测证据

- 单元测试覆盖 `Alt + F1`、`Ctrl + Shift + 2`、仅修饰键、取消、清空、无修饰字母拒绝、旧别名显示和重复识别。
- 源码与安装版 E2E 均完成 `Alt + F1` 键盘事件 → 设置保存 → `globalShortcut.isRegistered()` → 工作台回显。
- 两块不同 DPI 显示器连续 5 次捕获均使用 `windows-gdi`，覆盖窗口增长为 0，未发生 DXGI 回退或超时。
- 当前 Codex GUI 运行在隔离桌面，GDI 无法看到任何 Electron/WinForms 测试窗；因此本轮没有伪造绿色像素见证结论，只保留非黑图、窗口可见状态和后端不回退验证。此前 v1.1.7 交互桌面验收已通过绿色见证像素。

## 保留边界

- Windows 明确保留的组合键可能无法注册，软件会提示但不会绕过系统限制。
- DRM、系统安全桌面和受保护视频仍可能由 Windows 强制显示为黑色，软件不会尝试规避。
