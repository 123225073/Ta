# Ta Windows v1.1.2 选区交互对抗式审查

审查日期：2026-08-27

## 第一性原理判断

选区在鼠标松开后必须成为一个持续存在、可再次编辑的对象。后续左键操作需要先判断命中位置：选区内部代表移动，四边或四角代表缩放，遮罩空白处才代表重新框选。提交截图是独立动作，不能与首次松开绑定，否则用户无法继续调整选区。

旧实现没有这层状态区分：根覆盖层每次收到左键按下都会覆盖起点，四个白角也没有事件处理，因此“框内拖动”必然退化成新框选，“缩放”在结构上不可能发生。

## 攻击面与结果

| 攻击场景 | 预期约束 | 自动验证结果 |
|---|---|---|
| 首次拖动后立刻松开 | 选区持续存在并进入可编辑态 | 通过 |
| 在选区中央再次拖动 | 保持宽高，只改变位置 | 通过 |
| 从四边和四角拖动 | 8 个方向均能缩放 | 通过 |
| 从右下向左上反向框选 | 自动归一化为正宽高矩形 | 通过 |
| 移动到显示器外 | 完整选区被限制在当前显示器内 | 通过 |
| 缩放柄越过对边或输入极端坐标 | 最小宽高保持 4，矩形不翻转、不消失、不越界 | 通过 |
| 指针拖出元素边界后松开 | 覆盖层持有 pointer capture，结束事件不丢失 | 通过 |
| 点击工具栏 | 不向覆盖层冒泡，不误启动新框选 | 通过（结构审查） |
| 真实 Electron 输入链 | 创建、松开保留、移动、缩放、8 个控制点 | 通过 |

## 验证证据

- `npm test`：5 个测试文件、21 个测试全部通过，其中 6 项为选区状态机与极端边界测试。
- `npm run smoke:e2e`：真实桌面 3073×1921，覆盖层 1/1；Electron 鼠标事件完成创建、移动与缩放，8 个控制点均被检测。
- 安装版 `verify-installed.ps1`：v1.1.2.0 上重复通过相同交互链路。
- `npm audit --omit=dev`：0 个生产依赖漏洞。

## 保留边界

- 松开鼠标的含义是“确认当前选区并允许继续调整”，不会立刻导出图片；导出可用双击选区、点击“完成”或按 `Enter`。
- 每个显示器使用独立覆盖层，选区仍不能跨越多个显示器边界。
- 当前没有实现窗口边缘自动吸附；这不影响自由框选、移动和缩放。
