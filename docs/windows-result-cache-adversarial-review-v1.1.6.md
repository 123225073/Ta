# Ta Windows v1.1.6 结果缓存对抗审查

日期：2026-08-28

## 第一性原理

工具结果必须同时绑定“当前截图”和“具体功能”。切换面板只改变正在查看的结果，不应等同于重新执行；重新执行必须是用户可感知、可主动触发的操作。

## 原因

旧结果页只有一份共享的文本和加载状态。每个工具按钮都会先清空这份状态并立即调用 OCR 或云端接口，所以切回必然重跑；快速切换时，旧请求还可能覆盖当前面板。

## 修复

- 使用 OCR、AI 识图、翻译三份独立状态，分别保存加载、成功、取消、错误、文本和 OCR 元信息。
- 缓存生命周期限定在当前截图；截图 ID 改变、标注或美化生成新图时统一重置。
- 每次运行分配单调递增的请求 ID，只接受当前工具最新一次请求的响应。
- 普通点击优先展示已有结果；“重新识别”强制创建新请求。
- 对取消上传错误做语义化处理，不泄露 IPC 包装文字。

## 对抗用例

- AI 识图成功 → 翻译成功 → 返回 AI：识图请求次数仍为 1，原结果完全保留。
- 点击重新识别：识图请求次数从 1 变为 2，新结果覆盖旧结果。
- 同一工具连续产生两个请求：第一个请求较晚返回时不得覆盖第二个请求。
- 用户取消上传：显示未发送提示，切换回来不自动再次弹出上传确认。
- 新截图或编辑后的新图片：旧缓存不得继续显示。

## 同轮性能审查

安装版冷启动测试发现首次截图分配双显示器全分辨率位图时存在一次性抖动。捕获辅助进程现改为后台预分配并复用位图、响应后清黑；显示拓扑变化时重建。对抗复测还捕获到复用覆盖层未完成清空就被显示的竞态：现等待渲染确认后再显示；若 GDI 仍检测为黑图，则隐藏覆盖层后优先用预热 GDI 重试，最后才使用 Electron/DXGI。该链路不改变页面内容，并拒绝把检测失败的源图写入结果页或历史。
