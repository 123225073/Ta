# Ta Windows v1.1.5 黑图故障对抗审查

日期：2026-08-28

## 第一性原理

截图结果成立需要四个阶段同时正确：桌面像素被读取、预览只显示该冻结画面、选区映射到正确物理像素、最终 PNG 保留这些像素。窗口出现、图片有尺寸、文件有哈希都不能证明画面不是黑色。

## 复现证据

- 系统：Windows 10 build 19044，Electron 44，双显示器 3072×1920 + 2560×1440；Electron 主显示器物理源为 3073×1921。
- v1.1.4 真实 E2E 曾返回 `greenWitnessPixels=0`，用户结果页显示 1526×1179 的纯黑图片；同一路径重跑又可能恢复正常，证明是非确定性捕获问题。
- 故障发生在桌面源阶段：一旦源图为黑，预览、裁剪和落盘都会忠实地继续传播黑图。

## 假设与证伪

| 优先级 | 假设 | 预测 | 结果 |
|---|---|---|---|
| 1 | 全屏覆盖层的 `setContentProtection(true)` 被驱动呈现为黑色保护窗口 | 隐藏覆盖层后捕获恢复 | 成立；隐藏路径连续通过 |
| 2 | 预览缩放或裁剪把正常源变黑 | 源正常而裁剪黑 | 不成立；失败时已知颜色见证在源阶段即为 0 |
| 3 | 显示器 ID 映射错误 | 精确源与回退源不同 | v1.1.4 在单显示器仍可复现；v1.1.5 又完成双显示器逐屏尺寸、主屏身份与内容验证，排除映射为主因 |
| 4 | GPU 捕获随机失败且与覆盖层无关 | 隐藏覆盖层后仍随机黑 | 未出现；Electron 隐藏降级路径与 GDI 路径均连续通过 |

## 修复设计

- Windows 10 不再依据版本号盲目信任 `WDA_EXCLUDEFROMCAPTURE`。
- Windows 10 的全部显示器优先使用隐藏、常驻的 Windows GDI 辅助进程；进程启动时只用 1×1 像素预热 GDI，不保存该像素，用户触发后才复制完整桌面。
- 辅助进程先把全部屏幕复制到内存，生成轻量 JPEG 冻结预览并回报“像素已冻结”，随后才写入原始 BGRA；避免第一块屏幕编码期间第二块屏幕内容继续变化，也避免鼠标等待约 38 MB 原始像素落盘。
- 主进程校验辅助进程返回路径、字节长度、图片有效性和像素内容；临时原图与预览读入内存后立即删除。
- Windows 11 的早显覆盖层路径增加黑图检测；异常时隐藏覆盖层、关闭内容保护并重新捕获。
- 辅助进程失败时走隐藏覆盖层的 Electron 降级路径，优先保证正确性。

## 对抗用例

- 完全纯黑图片：必须判为黑图。
- 深色背景加少量文字/色块：不得误判。
- 首次截图、连续截图、覆盖窗口复用：源图均不得为黑。
- 双显示器必须先完成全部像素复制，且真实冻结预览已经送达，才显示可见框选层；输入遮罩、首次/连续冻结画面、全分辨率源分别设置独立时延上限。
- 启动阶段和裁剪阶段各做 30 帧真实鼠标事件监控；必须收到至少 12 次指针移动，最大帧间隔不超过 80 毫秒、平均不超过 30 毫秒。
- 已知绿色见证区域：必须存在于冻结源和裁剪结果。
- 捕获结果实际写入隔离历史目录后：PNG 仍不得为黑。
- 清空历史后重新截图：索引、PNG 和结果页必须恢复。
- 禁用原生捕获辅助进程：Electron 降级路径仍正确。
- 退出 E2E：不得残留截图辅助进程或新增临时目录。

## 剩余边界

- Windows 受 DRM/内容保护的应用仍可能按操作系统策略显示黑色，这不是截图软件能够绕过的范围。
- 商业发布仍建议对安装程序和辅助脚本做代码签名，减少 SmartScreen 提示。
