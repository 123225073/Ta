# Ta Windows v1.1.3 截图启动延迟审查

审查日期：2026-08-27

## 结论

用户感受到的延迟真实存在。旧版从触发到覆盖层可框选需要 1,388–1,426 ms；v1.1.3 多轮测得首次及连续第二次截图为 110–247 ms，缩短约 82%–92%。

## 分段证据

旧路径一次代表性测量：

| 阶段 | 耗时 |
|---|---:|
| 固定隐藏等待 | 126 ms |
| 全分辨率桌面捕获 | 601 ms |
| 新建并加载覆盖层页面 | 200 ms |
| PNG/Base64 编码 | 129 ms |
| 其余显示与渲染等待 | 约 204 ms |
| 合计 | 1,260 ms |

## 修复原则

“用户何时能开始框选”和“原始桌面何时完成冻结”不必串行。应用启动后提前创建隐藏覆盖层；触发截图时先显示已加载的透明交互层并接管鼠标，随后在后台捕获原始全分辨率桌面。Windows 捕获排除保证透明交互层本身不会进入截图。

预览只用于框选视觉，按逻辑分辨率生成高质量 JPEG；提交后仍从主进程保存的原始 `NativeImage` 裁切，因此不会牺牲最终清晰度。

## 对抗验证

- 加强捕获隔离校验后的连续三轮 E2E：235/147、144/169、176/247 ms，均低于 300 ms 门槛。
- 同一进程第二次截图使用全新预热覆盖层，选区状态不会残留。
- 创建已知绿色见证窗口，再从受保护覆盖层下方抓屏，验证绿色区域仍存在，证明覆盖层未污染冻结画面。
- 覆盖层出现后立即执行新建、移动、缩放，全部通过。
- 快速取消会递增捕获代次；旧异步捕获完成后不能写入新会话。

## 兼容边界

提前显示依赖 Windows 10 2004（build 19041）及更新版本的 `WDA_EXCLUDEFROMCAPTURE`。旧版 Windows 自动保留先抓屏、后显示覆盖层的安全路径，以避免黑屏或把覆盖层截入结果。
