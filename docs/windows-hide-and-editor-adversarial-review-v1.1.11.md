# Ta Windows v1.1.11 隐藏残影与标注适配对抗审查

日期：2026-08-28

## 审查目标

1. 用户选择“自动隐藏 Ta”后，截图中不能出现主窗口本体、淡化动画或旧合成帧；
2. 其他应用必须保持原来的可见性和窗口状态；
3. 大图进入标注时必须先完整可见，不能先放大一帧，也不能因为工具栏占用高度而裁掉内容；
4. 修复不能破坏截图延迟、指针流畅度、智能框选、自动复制、钉图、结果缓存或历史记录。

## 第一性原理分析

### 隐藏残影

`BrowserWindow.isVisible() === false` 只证明 Electron 的逻辑窗口状态，不证明 Windows 桌面合成器已经提交了新的画面。原实现调用 `hide()` 后仅等待最多 32ms，GDI `CopyFromScreen` 可能读到 DWM 保留的上一帧或淡出动画，因此出现“窗口已经隐藏，但截图里还有一层虚影”。

修复将可见性判断升级为像素事实：Ta 在隐藏前显示唯一洋红色测试块，冻结截图后在相同物理坐标统计像素。生产路径使用透明度归零、隐藏和 DWM 双帧同步，确保 GDI 读取的新合成帧中已不存在 Ta。

### 标注放大

Canvas 的 `width`/`height` 是输出像素尺寸，不能直接作为屏幕布局尺寸。原 CSS 只写 `max-width/max-height: 100%`，但网格、内边距和工具栏共同参与布局，2612×1526 画布最终按宽度缩放到 1109×648，而实际可用高度只有 522，形成纵向滚动和不可见区域。

修复把输出像素和显示尺寸分离：Canvas 仍保留原始像素用于无损导出，CSS 宽高使用 `min(1, 可用宽/原宽, 可用高/原高)`；指针位置继续按 `canvas.width / boundingRect.width` 反算到原图坐标。

## 红测证据

修复前真实 Windows E2E：

- Ta 唯一标记：隐藏前 `106038` 像素，截图源仍有 `96962` 像素，逻辑隐藏但视觉上几乎完整残留；
- 大图：原图 `2612×1526`，显示 `1109×648`，标注区可用 `1109×522`；纵向溢出为 `true`。

## 绿测证据

修复后真实 Windows E2E：

- Ta 唯一标记：安装版隐藏前 `106449`，截图源 `0`；
- 其他绿色见证窗口仍被捕获，证明没有为了隐藏 Ta 而隐藏全部应用；
- 大图：显示 `926×541`，可用区域 `1123×541`；横向和纵向溢出均为 `false`；
- 在适配后的 Canvas 中用真实鼠标事件创建箭头标注，标注计数从 0 变为 1；
- 安装版双屏截图接管输入 50ms，冻结像素 305ms，完整预览 444ms；连续截图为 41/279/386ms；
- 启动和框选移动的最大帧间隔分别为 17ms 和 9ms；
- 智能窗口框选、单击锁定、四块外遮罩、选区原色、移动、八方向缩放、双击确认、自动复制、快速截图不进编辑页、同图 AI/翻译缓存、钉图操作、快捷键注册、黑图/透明图检查和覆盖层复用全部通过。

## 对抗场景

| 场景 | 防线 | 结果 |
|---|---|---|
| `hide()` 已返回但 DWM 仍保留旧帧 | 透明度 0 + SW_HIDE + 两次 `DwmFlush` | 截图源残留 0 像素 |
| Ta 再次从托盘打开仍为透明 | `createMainWindow/showRoute` 显示前恢复透明度 1 | 通过 |
| 外部软件被误隐藏 | 只操作 Ta 的 BrowserWindow；外部见证窗口做像素检查 | 通过 |
| 4K/高 DPI 大图按宽度适配后高度溢出 | 同时取宽、高最小比例 | 通过 |
| 超大长图所需比例低于 5% | 允许比例低至 0.1% | 单元测试通过 |
| 小图被自动放大 | 最大初始比例限制为 100% | 单元测试通过 |
| 适配计算前闪现原始尺寸 | `fitReady` 前画布不可见 | E2E 未观察到可操作放大帧 |
| 缩放后标注位置漂移 | DOM 坐标按物理 Canvas 比例换算 | 真实输入标注通过 |

## 剩余边界

- DRM 或系统保护内容可能由 Windows 强制返回黑色，这是操作系统保护边界；
- 极端高负载时单次帧间隔可能出现瞬时抖动，因此 E2E 同时检查平均帧间隔和重复运行，不以一次偶发调度峰值替代功能结论；
- 用户主动放大画布后允许滚动，这是编辑能力，不属于初始裁切回归。
