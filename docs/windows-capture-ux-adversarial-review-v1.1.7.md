# Ta Windows v1.1.7 截图体验对抗审查

审查日期：2026-08-28

## 第一性原理

截图链路必须同时满足四个不变量：采集源是用户触发瞬间的桌面；覆盖层自身不能进入采集源；除用户明确选择外不改变任何应用窗口；确认后结果必须持久化并可立即粘贴。结果工具还必须把“长内容滚动”和“固定操作”分离，不能让内容高度挤走复制入口。

## 先失败、后修复的证据

| 攻击场景 | 修复前证据 | 根因 | 修复与回归门槛 |
|---|---|---|---|
| 连续复用截图覆盖层 | 三次源图亮度由 156.61 降到 104.21、70.65；绿色见证像素连续为 0 | 透明 Electron 覆盖层仍可能以旧合成帧进入 GDI 位图，形成“截图套截图”的暗化反馈 | GDI 期间原生透明度为 0；新预览绘制两帧后才显示；连续 5 次亮度稳定且见证窗口每次存在 |
| 快速双击确认 | 原生输入模拟后 `doubleClickConfirmed=false` | 指针捕获与透明窗口下 DOM `dblclick` 不稳定 | 两次短按在 420 ms、8 px 内视为确认；原生双击 E2E 必须关闭覆盖层并产生新结果 |
| 长识别内容 | 侧栏内容挤出底部复制按钮 | Grid/Flex 子项缺少完整的 `min-height: 0` 与溢出边界 | 内容区独立滚动到底；底部操作区必须始终位于侧栏边界内并可点击复制 |
| 截图窗口被隐藏 | 主窗口无条件调用 `hide()`，用户无法选择 | 隐藏策略硬编码 | 设置页提供隐藏/保留/每次询问；保存后真实截图时序必须采用相同策略 |
| 其他应用状态 | 用户观察到其他软件似乎消失 | 全屏暗层造成视觉误判；代码只隐藏 Ta 主窗口 | 见证窗口在隐藏 Ta 和保留 Ta 两种模式下均保持可见；无枚举或隐藏外部进程的代码 |
| 截图后不能直接粘贴 | 只有“复制截图”动作写剪贴板 | 普通截图路径未执行剪贴板写入 | 通用截图等全部默认复制；E2E 比较剪贴板图片哈希与落盘 PNG |
| 标题不能拖动 | `.brand` 被整体标记为 `no-drag` | 品牌标题被当作普通按钮 | 品牌标题为 `drag`，导航和窗口按钮为 `no-drag`，三者分别断言 |

## 对抗范围

- 两块不同缩放比例显示器、首次与连续截图、覆盖窗口复用增长、鼠标启动与裁剪帧间隔。
- 创建、松开保留、移动、八方向缩放、原生双击确认、按钮确认边界。
- Ta 隐藏、Ta 保留、设置页保存三态策略、其他可见窗口不受影响。
- 空历史删除后恢复、钉图拖动/工具栏/穿透恢复/关闭/任务栏排除。
- 长 AI 结果滚动、固定复制按钮、工具缓存切换、显式重新识别。
- 原生 GDI 与禁用原生辅助进程后的 Electron 捕获链路；源图、裁剪图、落盘图均执行非黑/非透明内容检查。

## 保留边界

- Windows 或显卡驱动对 DRM、受保护视频和系统安全桌面的黑屏属于操作系统保护边界，软件不会尝试绕过。
- “每次询问”会增加一次人工确认；默认仍为“自动隐藏 Ta”，保持日常截图的低延迟。
- E2E 能证明应用没有隐藏其见证窗口且代码没有外部窗口隐藏路径；第三方软件自身的最小化、独占全屏或防截屏策略仍由其自身控制。
