## 验收中发现并修复的问题

- 旧界面只有结果工具栏提供复制/保存，工作台、素材库、编辑画布和钉图中的图片无法直接复用。v1.3.3 由主进程统一创建 Windows 原生右键菜单，并按入口解析原图或当前渲染画布。
- 对抗检查发现编辑画布的非左键指针事件可能启动一个空标注。v1.3.3 明确只允许左键开始绘制，并在 E2E 中验证右键后对象数量保持不变。
- 桌面像素见证可能在外部前台窗口遮挡主窗口时得到“隐藏前 0 像素”。验收现只在隐藏前目标像素真实可见时做前后比例断言，避免把未出现的目标错误归因于隐藏逻辑。
- 旧长截图拼接器只根据相邻帧重叠裁掉新帧顶部，却会把选区内固定的浏览器栏、网页吸顶栏和底部悬浮栏随每帧再次附加。v1.3.2 先从多帧边缘识别固定带，只对中间滚动正文做位移匹配，最后把第一帧顶栏与末帧底栏各合成一次。
- 长截图进度原先只写入托盘提示和隐藏的主窗口，用户在目标页面上看不到任何工作状态。v1.3.2 新增不抢焦点的独立状态浮层，并在 GDI 读取每一帧前将其透明化和隐藏，避免状态 UI 污染截图。
- 对抗式安装复验发现设置页和标注页的 E2E 偶尔在 React 状态水合前继续执行，造成一次智能框选和一次编辑器误报。最终验收改为明确等待真实设置值、大图结果与编辑器画布分别就绪；最终安装包连续两轮完整 E2E 通过。
- v1.3.0 对抗审查发现设置曾保留“收集该软件复制的所有图片”的兼容模式，这与“普通复制不自动进入”冲突。最终版已移除该入口，旧值加载时自动收紧为严格模式，分类器本身也失败关闭。
- 飞书快捷键意图原先只要求切换到可信、可见、置顶的飞书窗口。最终版进一步要求该窗口是无标题栏的弹出层且覆盖当前显示器至少 70%，排除会议浮窗和最大化普通窗口；仍绑定物理快捷键、窗口 PID/完整路径、剪贴板 sequence 和关闭后 1 秒竞态窗口。
- 外部截图原先只把软件名写入默认标题，素材卡的来源徽标没有持久化依据。最终版为 SQLite 增加可兼容迁移的 `source_app` 字段，新素材准确显示飞书、微信或 QQ，旧素材继续显示通用“外部截图”。
- 打开第 51 张以后的素材时，主进程原先从“最近 50 张”列表回查动作和时间，可能退化为当前时间。现在按 ID 直接读取 SQLite 元数据，不再受首页最近列表上限影响。
- v1.3.0 UI 初版的成功提示会短暂跨页覆盖素材/画布，素材页入场动画也漏过减少动态效果设置。最终版在页面切换时清除提示，保留 2.6 秒同页自动消失，并补齐 `aria-live`、工具 `aria-pressed`、素材文字对比度与素材页减弱动态效果。
- v1.2.0 初版外部来源判断曾允许通用快捷键意图旁路 QQ 严格规则。最终版只允许飞书消费意图，拒绝注入按键，并绑定真实可见置顶飞书截图浮层的 PID、完整路径和新剪贴板 sequence；浮层关闭后只保留 1 秒提交竞态窗口。
- 素材库初版曾存在跨时区重分组、迁移期内存排队、暂存排空丢唤醒和损坏项阻塞后续导入风险。最终版持久化 `dateKey`，使用有界磁盘暂存、恢复校验、单线程排空和损坏隔离，并由 85 项测试与真实 E2E 覆盖。

- v1.1.10 只调用 `BrowserWindow.hide()`，Windows DWM 在少数帧仍可能保留 Ta 的合成表面，形成用户看到的淡色虚影。v1.1.11 在隐藏前把窗口透明度原子设为 0，GDI 抓取前跨越两次 DWM 合成边界，并用同坐标像素计数验证由 106,449 降至 0；恢复窗口时透明度回到 1。
- 标注页原先仅按宽度约束 2612×1526 Canvas，工具栏和内边距占用高度后会溢出，并在适配前短暂显示原始尺寸。v1.1.11 将输出像素与 CSS 显示尺寸分离，按真实可用宽高共同适配，适配完成前不显示画布，并增加缩放及“适应窗口”；真实标注坐标仍回写原图像素。
- 双显示器全分辨率 PNG 原先串行编码，安装版冻结耗时一度达到 813/783 ms。v1.1.11 对每块独立位图并行无损编码，安装版降至 305/279 ms；没有降采样、JPEG 或清晰度交换。
- 自动化验收会覆盖整个桌面，真实用户鼠标输入和动态前台窗口曾污染选区与窗口标题断言。v1.1.11 的 E2E 模式增加仅测试时启用的输入隔离，并以实际 Win32 候选坐标而非固定窗口标题验收；正常产品路径不启用该分支。

- v1.1.9 为降低初次冻结耗时，把 3072px 主屏预览限制为 896px 宽，使用双线性插值后以 JPEG 76 保存；覆盖层再放大约 3.43 倍，造成用户看到的文字和细线发糊。v1.1.10 改为直接保存同一冻结位图的全分辨率无损 PNG，并新增逐屏尺寸、格式和预览/最终源像素一致性回归。
- “复制图片”在所有截图均已默认复制后语义重复。v1.1.10 将其统一为“快速截图”：沿用旧 `copy` 内部标识和快捷键以兼容用户配置，但完成后自动复制、保存到最近拓片、关闭覆盖层且不导航到编辑页。
- 旧覆盖层用全屏 `::after` 先压暗所有像素，再用透明选区与超大外阴影标记区域；透明元素无法挖穿已有暗层，所以选区必然发灰、四周还会双重变暗。v1.1.9 改为只覆盖选区外的上/右/下/左四片中性灰蒙版，候选与锁定选区本身不叠加颜色或滤镜。
- 旧版没有窗口候选，用户每次都必须从零拖框。v1.1.9 在同一次 GDI 冻结时枚举 Win32 顶层窗口，优先取 DWM 可见边界、保留 Z 序、排除覆盖层/最小化/cloaked/系统桌面窗口，并按显示器物理边界裁剪后转换为本地 DIP。
- 自动框选若在每次鼠标移动时调用 Win32/UIA，会重新制造用户此前报告的停顿。当前实现只在截图开始时生成一次候选；鼠标悬停阶段只做渲染进程内数组命中。单击锁定、移动超过 4 DIP 改为自由框选，锁定后继续支持移动、缩放与双击确认。

- v1.1.4 把 Windows 10 build 19041 以上等同于“全屏窗口可稳定排除捕获”，本机 build 19044 实测同一路径会在正常画面与纯黑画面间波动。v1.1.5 在 Windows 10 停用该高风险路径；多显示器改用预热的隐藏 Windows GDI 捕获，Windows 11 保留快速保护路径但增加黑图检测和隐藏重试。
- 旧 E2E 只检查尺寸、哈希和绿色见证区域，没有把“整图或裁剪图近乎纯黑”设为独立失败条件。现在源图、见证裁剪、实际落盘 PNG 和 4 次后续截图均检查平均亮度、亮度方差和近黑像素占比。
- Windows 原生捕获辅助进程在应用启动后预热，截图时不再支付 PowerShell 冷启动成本；双显示器先在内存中完成全部像素复制并生成全分辨率无损冻结预览，再写入原始 BGRA。v1.1.8 不再因内容接近纯黑而自动切换整个多屏后端；辅助进程真正失败时会关闭覆盖层并明确报错，不把失败源交给预览或历史记录。
- 安装版冷启动对抗测试还发现首次点击时创建双显示器全分辨率位图会产生分配抖动。v1.1.6 改为辅助进程启动时预分配、截图完成后清黑复用，显示拓扑变化时自动重建；既缩短首次路径，也不在辅助进程中继续保留桌面像素。
- 复用覆盖层在极端调度下可能尚未清除上一轮暗色背景便参与 GDI 捕获。现在 Windows GDI 采集期间覆盖层原生透明度固定为 0，新冻结画面绘制两帧后再显示；不再根据画面亮暗在 GDI 与 Electron/DXGI 间切换。
- 钉图的鼠标穿透原先只有托盘恢复路径，点击后钉图仍能显示悬停提示，却无法拖动、关闭或操作按钮。现在鼠标移回右上角工具栏会自动取消穿透，托盘恢复继续作为兜底。
- 钉图原先是无所有者的 Windows 顶层窗口，每张钉图都可能增加一个任务栏图标。现在钉图归属于主窗口，并在创建和显示后再次执行任务栏排除。
- 清空最后一条历史后，截图文件和索引虽已重新写入，但同一 HTML 文档只改变 hash 时 React 不会重新读取初始路由，界面因此看起来“完全没反应”。现在主进程向现有页面发送显式导航和历史变更事件。
- 截图覆盖层原先在每次截图结束后销毁并重建，连续 3 次会新增 3 个窗口。现在按显示器持久复用覆盖窗口，并用捕获代次重置选区，连续测试增长为 0。
- 截图触发原先要串行完成固定等待、全屏抓取、创建并加载 Electron 页面、PNG/Base64 编码后才显示覆盖层，实测需要 1.26–1.43 秒。现改为预热独立透明覆盖层：安装版约 0.04–0.07 秒接管输入但不改变页面，首次约 0.53 秒/连续约 0.39 秒完成全分辨率无损预览；最终裁图继续使用主进程保存的原始像素。
- 原生辅助进程最初对每块显示器执行“抓取、落盘、编码”后才处理下一块屏幕，会让第二块屏幕继续变化，也让鼠标等待编码。现改为先连续复制全部显示器，再生成轻量冻结预览，最后写入全分辨率原图。启动阶段 30 帧实测最大/平均间隔为 16–17/8–9 毫秒，裁剪阶段为 9/8 毫秒。
- Windows 选区原先把每一次左键按下都解释成“新建选区”，四角控制点也只有视觉效果。现已改为新建/移动/八方向缩放三态交互；首次拖动松开即保留选区，框内拖动移动，四边四角缩放，双击或完成按钮可提交，`Enter` 只作为可选快捷键。
- 首版全屏选区只依赖一次性 IPC 事件；渲染层加载很快时可能错过初始化内容，停在“正在读取屏幕”。已改成事件通知和主动重取状态双通道，并在打包版 E2E 中验证 1/1 个显示器选区窗口收到截图。
- 自动截图翻译在设置对象尚未加载时可能绕过上传确认。已改为默认确认，只有用户明确关闭该开关才跳过。
- OCR/AI 结果复制原先依赖渲染层浏览器权限。已改为 Electron 主进程剪贴板接口。
- 截图完成后销毁覆盖层时，`closed` 回调会再次读取已销毁的 `webContents.id`，导致 `Object has been destroyed`。现已缓存 ID 并把批量关闭改为先清会话、后销毁的幂等流程。
- 模型标签原先只显示配置项，没有说明实际路由。现在明确显示“当前”服务、模型和待保存状态；AI 识图/翻译面板同步显示实际服务，本地 OCR 与不调用云端的功能也有清晰说明。
- 已从“风沙 SAP 运维任务台”通过旧 Electron 运行时和匿名管道迁移 CPA 凭据，再由 Ta 重新使用 Windows `safeStorage` 加密；仓库、命令行和设置文件均没有明文 Key。
- AI 识图、截图翻译和本地 OCR 原先在工具间切换时都会重新执行。现在当前截图分别缓存三个工具的结果，切回时直接恢复；只有点击“重新识别”才再次请求。新截图或标注、美化生成新图片时自动清空，旧请求晚到也不会覆盖新结果。
- 长结果原先可能让侧栏随内容扩张，把“复制文字”挤出窗口。v1.1.7 固定侧栏高度和底部操作区，只让内容区独立滚动；真实长文本完成滚到底与按钮点击验证。
- 截图入口原先无条件隐藏 Ta，用户无法保留窗口或临时决定。v1.1.7 增加隐藏、保留和每次询问三态；执行路径只操作 Ta 主窗口，其他应用保持原样。
- 覆盖层虽然清除了 React 选区状态，但 Windows 合成器仍可能保留旧透明表面，连续 GDI 截图会逐次变暗。v1.1.7 在像素采集期间使用原生 0 透明度，冻结预览绘制两帧后才显示；对抗测试从“亮度递减且见证像素为 0”转为连续稳定。
- 透明覆盖窗口下浏览器 `dblclick` 事件并不可靠。v1.1.7 改为 420 ms/8 px 内两次短按确认，并用原生鼠标输入验证结果提交与自动复制。
- 普通截图原先只写历史，只有专用“复制截图”动作才写剪贴板。v1.1.7 所有截图完成后默认复制；剪贴板异常只提示，不会让已经截到的图片或历史丢失。
- 品牌标题原先被标为 `no-drag`。v1.1.7 将标题恢复为拖动区，同时保留导航和窗口控制的点击区域。
- 全局快捷键原先是要求用户手写 Electron accelerator 的普通文本框。v1.1.8 改为只读键盘录制器：聚焦时暂停现有全局快捷键，识别修饰键与主键，`Esc` 取消、`Backspace/Delete` 清空；重复组合阻止保存，被系统占用则单独提示。
- 用户修改快捷键后，工作台仍显示写死的默认值。v1.1.8 改为读取实际已保存设置；空值明确表示禁用，并提供一键恢复 Windows 默认值。
- 双屏中任意一块接近纯黑时，旧逻辑会把所有已成功 GDI 画面整体替换成 Electron/DXGI；本机 DXGI 会长时间卡住或返回黑帧。v1.1.8 以逐屏 GDI 返回为权威结果，允许黑色或关闭的副屏作为合法内容，不再让单个副屏拖垮全部屏幕。
- 官方 npm 审计在交付前新增了 Vitest 文件读取/执行公告。构建期依赖已由 3.2.4 升级到 3.2.7，重新审计为 0 个漏洞。
